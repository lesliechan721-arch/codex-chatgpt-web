# 桌面多账号

点击侧边栏的当前账号，或打开“设置项 → 账号管理”。每次只启用一个账号。添加时填写本地名称和账号代理，再确认切换。切换会重启启动器；Codex 本身保持打开，切换后需手动重启 Codex 刷新模型列表。API Key 模式通过 provider 的 `model_catalog_url` 从服务接口读取模型目录，无需重新导出目录文件。

账号名称只是标签，重命名不会改变数据位置或登录。新账号使用空白登录环境和默认账号设置。完成登录、能力检查及对应模式所需的 MCP 配置后才能使用。未启用账号只显示上次登录检查结果，不执行后台登录或额度轮询。认证检查发现实际身份变化时，原会话和能力会被暂停；请退出后恢复原身份，或在新记录中登录其它身份。

## 设置归属

| 每个账号独立 | 应用共享 |
| --- | --- |
| 登录、浏览器存储、模型能力和交互设置 | 语言、窗口布局、开机启动和关闭行为 |
| MCP、Tunnel、上游配置及账号专属密钥 | API 服务地址、访问策略和客户端服务访问密钥 |
| 代理及认证、额度、诊断和网页恢复记录 | Codex 接入所有权及原始配置恢复依据 |

“系统默认”代理使用启动器最初启动时的代理环境。自定义 HTTP(S) 代理只属于该账号；切换前会恢复原始环境。代理应用失败会阻止该账号出站操作，需修改代理或切回其它账号。上游的“使用当前账号代理”保留原 `global` 配置值；独立直连和自定义代理覆盖仍可使用。

切换和移除会在主进程关闭新任务接纳，再检查 API 请求、浏览器执行、等待用户、保留执行、工具调用、登录和诊断。忙碌或不能确认空闲时会拒绝操作，不取消任务，也不登记稍后自动切换。目标账号本地环境加载失败时只自动恢复一次；恢复失败后可在账号管理页重试或选择其它账号。

## 在另一个账号继续任务

继续旧 Codex 任务时，目标账号使用自己的登录、模型、代理、MCP 和 Tunnel，并创建新的网页会话。必要的任务正文、工具结果和摘要会交给目标账号。这些内容可能包含用户自行写入的敏感信息。登录凭据、浏览器页面和工具执行权限不交接。

上下文由 Codex 当前请求提供，包括必要指令、工具调用与结果以及压缩摘要。切换先确认空闲，再停止运行环境、销毁旧页面并重启。A → B 或 A → B → A 都从当前请求建立新页面，不读取其它账号的响应缓存。历史工具调用仅作为上下文，不授予重新执行权限。

普通切换不复制任务。当前请求无需覆盖桥接程序过去接收的全部原始历史；有效压缩摘要也可提供上下文。本地 Web 路径忽略额外的 `previous_response_id`，不替仅提供旧响应 ID 和少量增量输入的客户端恢复未提供的历史。请求格式和现有工具、恢复协议的校验继续有效。

## 移除和兼容

移除需要二次确认。当前账号须先切到其它账号；最后一个账号可以先退出运行环境，再回到空列表。清理失败的记录保持禁用，并显示重试清理入口。项目文件、Codex 自身历史、共享服务访问密钥以及其它账号的恢复记录会保留。此操作不注销线上 ChatGPT 账号，也不撤销线上 Tunnel。

升级时原登录和配置登记为默认账号，并保留其原目录与浏览器分区。新增账号目录由内部随机标识确定。默认账号与应用根共用物理目录，因此删除使用明确账号数据清单，保留共享配置、其它账号及程序资源。生产和开发环境各自管理账号列表。

远程 API 继续使用相同服务地址和服务访问密钥，请求由当前账号执行。API 没有账号选择或账号管理参数。没有可用账号时返回未就绪，API Key 鉴权仍然执行。CLI 保持原单配置方式。
